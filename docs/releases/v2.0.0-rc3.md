## Bundled fix — Python 3.11 compatibility in cleanup-coverage test

The pythonpath fix surfaced a second pre-existing bug in PR #5's first CI run. Python 3.12 + 3.13 cells went **GREEN** (first green in 80+ runs!); Python 3.11 hit an `INTERNALERROR` mid-suite:

```
INTERNALERROR>   File "D:\a\Curator\Curator\tests\unit\test_services_cleanup_coverage.py", line 155, in _exists
INTERNALERROR>     return original_exists(self, follow_symlinks=follow_symlinks)
INTERNALERROR> TypeError: Path.exists() got an unexpected keyword argument 'follow_symlinks'
```

`pathlib.Path.exists()` gained the `follow_symlinks=` keyword argument in **Python 3.12** ([CPython gh-97527](https://github.com/python/cpython/issues/97527)). The test's monkeypatch wrapper was written assuming 3.12+. The 3.11 CI cell rejected the kwarg.

**Fix** (3 lines + 1 import):

```python
def _exists(self, *, follow_symlinks=True):
    if self == fake_link:
        return False  # broken
    # Path.exists() gained ``follow_symlinks`` in 3.12; 3.11 rejects the kwarg.
    if sys.version_info >= (3, 12):
        return original_exists(self, follow_symlinks=follow_symlinks)
    return original_exists(self)
```

**Why bundled, not split into rc4:** explicitly Jake's call via in-PR `AskUserQuestion`. The fix is mechanically minimal, single-CI-cycle close-out beats split-PR-cycle close-out, and the bug is causally connected to v2.0.0-rc3's "make CI green" goal. The brief's "don't rewrite tests" guidance was scoped around what we then thought was the only fix needed; new CI signal added new information.

**Why this bug existed for so long:** `test_services_cleanup_coverage.py` was introduced in v1.7.142 (per its module docstring). Local TDD (`python -m pytest`) and developer venv (currently 3.13) never tripped the 3.11/3.12 API gap. CI couldn't catch it either — the whole point of Lesson #108 is that CI was failing at collection long before any test ran. Two false-positive-green-light failure modes were stacked: the pythonpath one (Lesson #108 proper) hid the Python-version-compat one underneath. Removing the top one revealed the second.

**Doctrine implication:** future Python-version-spanning monkeypatches on stdlib APIs should default to a `sys.version_info` gate. Captured as an inline note in Lesson #108 (CHANGELOG), not promoted to a separate numbered lesson — the apex rule ("CI green is a separate signal from local green") is already there, and this is a concrete instance reinforcing it rather than a new doctrine line.

## The bug, plainly

`pytest (windows-latest / Python 3.{11,12,13})` workflow runs:

```yaml
- name: Run pytest
  run: pytest tests/ -q --tb=line --timeout=120 --cov=curator ...
```

That's **bare** `pytest` — the console-script entry point. It does **not** add the current working directory to `sys.path`. (Python's `-m` flag does; bare `pytest` does not.)

Ten test modules in `tests/unit/` use the shared-stub import idiom documented in `CLAUDE.md` §"Stub patterns (Lesson #84)":

```python
from tests.unit.test_migration_plan_apply import (
    NOW, StubAuditRepository, StubFileRepository, ...
)
```

`tests/__init__.py` doesn't exist; only the subpackage `__init__.py` files (`tests/unit/__init__.py`, `tests/integration/__init__.py`, etc.) do. Under `python -m pytest` (the local idiom in `CLAUDE.md` §"Running tests"), CWD is on `sys.path` so `tests` resolves as a PEP 420 namespace package and the imports work. Under bare `pytest` (CI), `tests` is unreachable. Result:

```
ImportError while importing test module 'D:\a\Curator\Curator\tests\unit\test_migration_autostrip.py'.
E   ModuleNotFoundError: No module named 'tests'
```

Affected modules (all 10 are stub consumers):

- `test_gui_main_window_part2_coverage.py`
- `test_gui_main_window_part3_coverage.py`
- `test_gui_main_window_part4_coverage.py`
- `test_gui_main_window_part5_coverage.py`
- `test_migration_autostrip.py`
- `test_migration_cross_source.py`
- `test_migration_dispatcher_coverage.py`
- `test_migration_execution.py`
- `test_migration_persistent_jobs.py`
- `test_migration_persistent_progress.py`

## The fix

```toml
# pyproject.toml
[tool.pytest.ini_options]
testpaths = ["tests"]
# v2.0.0-rc3: put the repo root on sys.path so the shared-stub import idiom
# ``from tests.unit.test_migration_plan_apply import (...)`` resolves under
# **bare** ``pytest`` invocation, not just ``python -m pytest``.
# [...]
pythonpath = ["."]
```

This is the documented pytest answer for the local-vs-CI invocation divergence — see https://docs.pytest.org/en/stable/reference/reference.html#confval-pythonpath. Available since pytest 7.0; Curator pins pytest ≥8.0 in `[project.optional-dependencies] dev`, so the dependency is already satisfied.

**Why not** `tests/__init__.py`: turns `tests` into a regular package, which subtly changes pytest's import mode behavior and could destabilize collection across modules with duplicate test-class names. **Why not** root `conftest.py`: works (pytest auto-adds the conftest's directory to `sys.path`) but is less explicit. **Why not** change CI to use `python -m pytest`: papers over the divergence; any developer running bare `pytest` would still see the same failure.

## Lesson #108 — pytest invocation divergence between local TDD and CI

Recorded in CHANGELOG and adopted as Doctrine #26 in `CLAUDE.md`.

`python -m pytest` and bare `pytest` are not interchangeable. Python's `-m` adds CWD to `sys.path`; bare `pytest` does not. For test suites using intra-`tests/` cross-module imports, the two invocations behave differently. The canonical fix is `pythonpath = ["."]` in `[tool.pytest.ini_options]`.

This sits alongside Lesson #93 (coverage continuity) and Lesson #107 (wire-format regression invisible to line+branch coverage) as one of three orthogonal false-positive-green-light failure modes:

- **#93** — "the new tests don't cover what the old tests did" → regression in *coverage scope*
- **#107** — "the source coverage is complete but the wire shape is broken" → regression in *observed surface*
- **#108** — "the local coverage is complete but CI's collector can't even reach the test code" → regression in *collector reach*

All three are now part of the apex-accuracy discipline. See CHANGELOG for the full lesson body.
